# 真实数据与敏感信息处理指南

本项目当前已进入真实数据验证阶段，但必须确保真实客户信息和敏感数据不被推送到公开或私有 GitHub 仓库中。

## 1. 重要原则

- 真实数据不应直接提交到仓库。
- 真实客户信息、供应商信息、合同数据、订单明细等均属于敏感信息，应严格隔离。
- 仓库中只能保存结构定义、业务模型、示例数据模板和测试脚本。
- 真实数据应存放在本地受控目录，并加入 `.gitignore`。

## 2. 本项目的做法

- 约定 `data/` 或 `private/` 目录用于保存真实数据样本和临时导出文件。
- `.gitignore` 已配置忽略 `data/`、`private/` 目录以及 `.env` / `.env.*` 文件。
- 真实业务演练时，尽量使用 `sample/` 中的模板文件，而不是直接保存真实文件。

## 3. 录入真实数据前的准备

执行以下步骤以保证敏感数据不进入仓库：

1. 确认本地目录中没有未跟踪的真实数据文件：

```bash
git status --short
```

2. 真实数据文件放在 `data/` 或 `private/` 目录，且这些目录不会被提交。
3. 真实数据处理结束后，不要把 `data/` 或 `private/` 目录中的文件加入 git。

## 4. 推送前的检查

在推送前必须确认：

- `git status` 没有显示真实数据文件。
- `.env` 或类似配置文件没有加入版本控制。
- `.gitignore` 中已经忽略了敏感数据目录。

如果你使用 GitHub 私有仓库，也仍需遵守相同规则：私有仓库不是敏感数据存储库。

## 5. 推荐流程

1. 先在本地执行真实数据测试。
2. 验证业务流程和数据模型。
3. 只将 schema、文档、脚本、模板和问题记录提交到仓库。
4. 对发现的问题生成 Issue 或 PR，不要提交真实业务文件。

## 6. 额外建议

- 如果需要多个人员共同测试，建议通过安全的数据交换渠道共享数据，而不是通过 GitHub。
- 对真实数据的导入/导出过程做好记录，避免重复提交敏感文件。
- 如果要保存测试结果，可使用脱敏后的数据或汇总报告，而非原始明细。
