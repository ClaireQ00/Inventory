# ADR(架构决策记录,Architecture Decision Records)

> 本目录把 `docs/DESIGN.md` 里**最关键的设计决策**单独固化成"一页纸一个决策"的标准 ADR 格式,供长期追溯。
> ADR **不重复** DESIGN.md 的内容,而是把某个决策的"上下文 + 决定 + 理由 + 后果"压缩到一页,便于:
> - 半年后有人问"当时为什么这么定"能直接找到答案
> - 决策被推翻时,有清晰的演化记录(状态从"已接受"变"已取代")
> - 新人 onboarding 时只看几条 ADR 就能抓住核心设计取舍

---

## ADR 是什么(给新手的一句话)

**ADR 就像会议纪要里的"决议"那一栏**——开会时大家讨论了半天、权衡了几个方案,最后拍板"我们选 X"。ADR 就是把"为什么选 X、不选 Y、选了之后付出什么代价"记下来,免得以后忘了当初为什么这么定。

跟普通文档的区别:普通文档讲"系统长什么样",ADR 讲"**为什么长成这样,而不是别的样子**"。

## 编号规则

| 规则 | 说明 |
| --- | --- |
| 文件名 | `NNNN-kebab-case-title.md`,四位数字从 `0001` 开始 |
| 编号含义 | 单调递增,**不复用、不改号**(就算决策被推翻,旧号也保留) |

## 如何新增一条 ADR

1. **先判断要不要进 ADR**。满足以下任一条件才进:
   - 讨论过备选方案、有明确取舍(不是"显然只有一个做法")
   - 决策影响多个文件/表/模块,改起来代价大
   - 决策来源于客户确认或外部约束(如 UCP600、汇率规则)
2. **取下一个编号**(看本 README 表格最大号 +1),文件名用 `kebab-case`(连字符小写)。
3. **按标准结构写**(下方模板)。每个小节都要有内容,不能空。
4. **代码证据必须真实**。引用的函数名/字段名/行号必须在 `sql/`、`tools/`、`scripts/` 里 grep 得到。引用 `docs/DESIGN.md` 用具体章节号(如 `DESIGN.md §2.2`),**不要复制内容**,只引用。
5. **真实数据不进 ADR**(`BUSINESS_RULES.md R8`)。示例编号用 `TR20260729001` 这种格式示例,不写真实客户/合同号。
6. **更新本 README 表格**,加一行索引。
7. **状态写法**:新建默认 `已接受 + 日期`;日后若被新 ADR 取代,旧 ADR 状态改 `已取代(被 ADR-NNNN 取代)`,但文件保留不删。

## ADR 标准模板

```markdown
# NNNN. 标题(一句话说清决定了什么)

## 状态 (Status)
已接受 / 已取代(被 ADR-XXXX 取代)/ 已废弃 + 日期(YYYY-MM-DD)

## 上下文 (Context)
- 为什么需要做这个决策?面临什么问题?
- 触发这个决策的业务场景 / 约束 / 痛点是什么?

## 决策 (Decision)
- 决定了什么?(一句话能说清最好)
- 关键参数 / 字段 / 边界。

## 理由 (Rationale)
- 为什么这么决定?
- 考虑过哪些备选方案?为什么否决?(不是走过场,要真实讨论)
- 代码证据:引用真实存在的函数/字段/行号。

## 后果 (Consequences)
- 正面后果:得到了什么?
- 负面后果 / 取舍:付出了什么代价?怎么缓解?

## 相关 (Related)
- 关联文档:`docs/DESIGN.md §X` / `docs/BUSINESS_RULES.md RX` / `docs/DATA_MODEL.md §X`
- 关联代码:`sql/01_schema.sql:NNN` / `tools/xxx.py:NNN`
- 关联 ADR:ADR-NNNN(如有)
```

## ADR 与项目其他文档的边界

| 文档 | 回答什么 | 跟 ADR 的关系 |
| --- | --- | --- |
| `BUSINESS_RULES.md` | 硬性业务规则(R1~R9) | ADR 引用规则号,不重复规则内容 |
| `DESIGN.md` | 每个设计决策的"为什么 + 代码证据" | ADR 是 DESIGN.md 关键决策的**单页摘要 + 长期追溯**;ADR 引用 DESIGN.md 章节,不复制 |
| `DATA_MODEL.md` | 表结构、字段、ER 图 | ADR 引用表名/字段名做证据 |
| `SPECS.md` | 功能需求 | ADR 不涉及功能清单 |
| ADR | **单个决策的取舍 + 演化记录** | 不讲"系统长什么样",只讲"为什么长成这样" |
